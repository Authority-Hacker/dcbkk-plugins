# Editing mode

Use this reference only when the user wants the draft changed.

## Frame the edit

Before editing, identify:

- The core point the draft must still make.
- The audience, publishing surface, and what the reader should think, feel, or do.
- Protected material: facts, links, citations, headings, placeholders, tables, frontmatter, code, quotations, and deliberate formatting.
- The voice cues already present or supplied by the user.

Useful voice cues include vocabulary, cadence, bluntness, humor, uncertainty, digressions, and how directly the writer addresses the reader. Keep this comparison internal unless it explains a consequential edit.

Ask one question only when the missing answer would materially change the edit. Otherwise infer and proceed.

## Minimum effective edit

Edit in this order:

1. Remove unsupported or empty framing.
2. Fix repeated template shapes and generic conclusions.
3. Untangle sentences that are genuinely hard to follow.
4. Replace vague abstraction with concrete detail already present in the source.
5. Stop when the remaining prose sounds intentional and belongs to the writer.

Do not rewrite a strong sentence merely to make the draft stylistically uniform. A rough line with character can be better than a polished line anyone could have written.

If no edit is justified, reproduce the source exactly, including paragraph breaks and formatting. Do not claim `Nothing` or `No edits needed` after making silent presentational changes.

Keep qualifiers such as "I think", "maybe", or "honestly" when they express real uncertainty, contrast, or spoken rhythm. Remove them when they only delay the point.

Use active voice when it clarifies who did what. Passive voice and inanimate subjects are not automatic errors.

## Preserve voice and structure

- Keep unusual specifics, real names, precise mechanisms, awkward-but-revealing admissions, and useful tension.
- Keep defended opinions, humor, bluntness, profanity, asides, fragments, and long spoken sentences when they are clear and characteristic.
- Preserve coverage and relative structure unless the structure itself creates repetition, fake suspense, or outline-like prose.
- When reorganizing materially, explain why briefly.
- Do not make every paragraph the same length or force every section into one formula.

## Typography and formatting

Formatting follows the content:

- Judge dash clusters by their effect and the supplied voice, not a quota. Keep an earned dash when it beats a comma, period, or parentheses; honor an explicit punctuation request in editable prose.
- Curly quotation marks are normal typography, not an error by themselves.
- Preserve lists that improve scanning. Convert a list to prose only when it is decorative or needlessly fragments two simple sentences.
- Preserve code blocks, tables, markdown links, citations, placeholders, headings, and quoted language unless the user explicitly requests a format change.

Direct quotations, citations, code, and other user-specified literal text remain protected even when they contain a flagged dash. If the user explicitly asks to change those literals, make the change and disclose it. An isolated earned dash in editable prose can also stay. Explain consequential `KEEP` decisions when a scanner runs.

## Strictness

- **Light:** Fix the loudest tells and clarity problems. Preserve nearly all structure and cadence.
- **Normal:** Remove repeated reflexes, filler, hype, and generic endings while preserving voice.
- **Aggressive:** Restructure where needed, but keep meaning, supported details, and recognizable voice. Aggressive never means inventing stronger claims.

## Completion

Compare the final text with the source using [`quality-gate.md`](quality-gate.md) when fidelity is uncertain. Return the complete edited draft with at most a short note on meaningful changes. Do not expose a verdict ledger unless the user requested an audit trail.
