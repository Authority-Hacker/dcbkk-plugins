# File and sibling jobs

Use this reference when the source or requested result lives in files.

Read only the named inputs and any named voice sample. Confirm which files are genuine variants of the same underlying piece before scanning them together. Keep their distinct surface constraints and requested structure.

Write one final output for each input, with an unambiguous source-to-output mapping. Use a sibling filename such as `draft-humanized.md` in the source directory or a user-named output directory; avoid overwriting the source unless requested. For detect-only work, write the requested findings report rather than a rewritten draft. Do not collapse several variants into one `final.md`.

If an output already exists, use a fresh filename unless the user asked to replace it. On a follow-up, revise the latest accepted output against the requested change while retaining the original as the fidelity reference. A request to shorten or simplify a passage changes its phrasing, not its substantive coverage, unless the user asks to cut content. Compare each revised passage with both the previous version and the original for lost propositions, qualifications and distinctive voice before checking the unchanged remainder. If the requested length cannot retain them, explain the tradeoff rather than silently dropping them. Keep prior results, preserve unaffected passages, and return the revised complete file rather than instructions for assembling patches.

For genuine siblings, read and scan the set together, then compare the finished set together. Remove repeated rhetorical scaffolding without erasing necessary shared facts, offer conditions, quotations or calls to action. Preserve each surface's distinct shape. An unchanged shared literal is not a reason to distort one variant.

For protected material, compare the actual source and output literals mechanically: URLs/link targets, placeholders, quotes, frontmatter, tables and code as applicable. Use the source's literal spans or a direct diff; do not assume a generic quote or number regex captures every protected item. Resolve differences or identify an explicitly requested change. Editorial comparison still owns coverage, facts, qualifications and voice; a clean literal check does not prove semantic fidelity.

Only create a separate compact audit note when the user requests an audit trail, the set is complex or high-stakes, or a check needs an explanation. Record consequential edits, protected `KEEP` decisions, unresolved scanner hits, and verification limits there. Keep private source text and reusable voice profiles out of the installed skill directory.
